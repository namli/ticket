## Запуск

1. Создай `~/.config/ticket/web.toml`. Пример лежит в `plugins/README.md`, раздел `ticket-web`.
2. Выполни `tk web`.
3. Открой `http://127.0.0.1:7420/`.

## Итоговая проверка

Независимый рецензент критичных ошибок не нашёл.
Он нашёл пять способов потерять или перепутать текст при сохранении.
Все пять исправлены, на каждый есть сценарий.

| Ошибка | Исправление |
|---|---|
| Два заголовка `## Design` в тикете: правка затирала не тот блок | Форма и запись берут первый блок, второй показан только для чтения |
| `id` в файле не совпадает с именем файла: название уходило в чужой тикет | Такой файл теперь `unparsable` |
| Сохранение меняло символы `CR` в заметках | Файл читается без преобразования; файл с CRLF теперь `unparsable`, как и для `tk` |
| POST без поля очищал блок текста | Сервер отвечает 400 |
| ID тикета с кириллицей ломал переход после сохранения | Ссылки кодируют ID |

## Решения, принятые при реализации

Эти решения принял исполнитель без согласования с владельцем.

| Решение | Цена ошибки |
|---|---|
| Настройки без единого `[[project]]` — ошибка запуска | Сервер нельзя запустить с пустым списком |
| Из шаблонов шагов убраны якоря `$`: Behave их запрещает | нет |
| Файл плана закоммичен вместе с задачей 1 | нет |
| Шагов отправки формы три, а не два | нет |
| Ожидание сортировки сводного вида в плане противоречило правилу «сначала приоритет»; тест исправлен | нет |
| `build_snapshot` принимает готовый отпечаток каталога | нет |
| Общий набор тикетов задаёт шаг, а не блок `Background` | нет |
| Заголовок колонки показывает число тикетов; сводный вид печатает ошибки проектов над колонками | косметика |
| Элементы связей несут `data-id`; тест читает его, а не текст ссылки | нет |
| Конец файла нормализуется, только если изменён последний блок | нет |
| Сохранение сохраняет права файла; тело формы ограничено 2 МБ | нет |
| Сбой `tk set` даёт 400, сбой записи файла — 500 с формой | нет |
| Если после `tk set` запись текста не удалась, новое название остаётся | Правка применена наполовину, форма это показывает |
| Сервер строит снимки всех проектов до печати адреса | Запуск дольше на один вызов `tk blocked` на проект |
| Поля поиска нет на форме правки | нет |
| Событие несёт имя только последнего изменённого проекта | нет |
| Сервер замечает закрытую вкладку в течение 15 секунд | Один простаивающий поток на закрытую вкладку |
| Ветка «файл исчез» внутри сохранения осталась без сценария | Непроверенная ветка с ответом 404 |
| Второе сохранение после конфликта может заменить чужую правку в поле, которое владелец не трогал | Нужно читать показанный текст с диска |
| Заголовок `## Acceptance criteria` в другом регистре — посторонний блок | Правка добавит второй блок |
| Запрос ждёт, пока идёт `tk blocked` | Медленный `tk` тормозит страницы этого проекта |
| Правка того же размера в тот же момент времени не замечается до следующего изменения | Редкая устаревшая карточка |

## Отложенные мелкие замечания

- Блокировка действует только внутри сервера. Запись агента между проверкой и сохранением после `tk set` теряется.
- Строка `## ` внутри блока кода делит блок на форме.
- Битые percent-байты в POST превращаются в `U+FFFD`, а не дают 400.
- Битая символьная ссылка `*.md` даёт ошибку «.tickets not found» для всей дорожки.
- Сохранение заменяет тикет-симлинк обычным файлом; `fsync` нет.
- Методы `HEAD` и `PUT` отвечают 501 без проверки `Host`.

## Известные ограничения

- Доска показывает рабочее дерево по указанному пути. Тикет, закрытый в другой ветке или в worktree, остаётся открытым на доске до слияния.
- Правка остаётся незакоммиченной в каталоге того проекта.
- Каждая открытая вкладка держит одно соединение для событий. Браузер разрешает около шести на один адрес.
- Скрипты публикации в Homebrew и AUR не знают о зависимостях плагина: Python 3.11+ и `ticket-set`.
