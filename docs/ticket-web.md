# ticket-web: веб-доска для тикетов `tk`

Плагин `ticket-web` добавляет команду `tk web`.
Команда запускает локальный веб-сервер.
Сервер показывает тикеты нескольких проектов на одной странице.

Документ состоит из двух частей:
- [Часть 1. Как пользоваться](#часть-1-как-пользоваться)
- [Часть 2. Как работает](#часть-2-как-работает)

## Термины

Документ использует каждый термин только в одном значении.
Значения терминов находятся в файле [glossary.md](glossary.md).

# Часть 1. Как пользоваться

## 1. Требования

| Компонент | Требование |
|---|---|
| Python | Версия 3.11 или новее |
| `tk` | Команда `tk` находится в `PATH` |
| Каталог `plugins/` | Каталог находится в `PATH` |
| `ticket-set` | Плагин нужен для правки названия |

Сторонние пакеты Python не нужны.

## 2. Установка

1. Обнови репозиторий: `git pull`.
2. Проверь версию Python: `python3 --version`.
3. Проверь, что `tk` видит плагин: `tk help`.

Строка `web` в выводе `tk help` подтверждает установку.

## 3. Настройка

### 3.1. Создай файл настроек

1. Создай каталог: `mkdir -p ~/.config/ticket`.
2. Создай файл `~/.config/ticket/web.toml`.
3. Добавь в файл по одному блоку `[[project]]` на каждый проект.

Пример:

```toml
port = 7420

[[project]]
name = "ticket"
path = "~/www/ticket"

[[project]]
name = "eagle"
path = "/home/me/www/eagle"
color = "#3b82f6"
```

### 3.2. Ключи файла настроек

| Ключ | Обязателен | Правило |
|---|---|---|
| `port` | нет | Число от 0 до 65535 |
| `name` | да | Уникальное имя. Разрешены символы `A-Z`, `a-z`, `0-9`, `_`, `-` |
| `path` | да | Корень проекта. Символ `~` означает домашний каталог |
| `color` | нет | Цвет CSS. Без ключа сервер выбирает цвет по имени |

Правила:
- Порядок блоков `[[project]]` задаёт порядок дорожек.
- Сервер читает файл настроек один раз при запуске.
- Файл настроек относится к одному компьютеру. Не добавляй его в репозиторий.

### 3.3. Путь к файлу настроек

Сервер выбирает путь в таком порядке:

1. Параметр `--config`.
2. Переменная окружения `TK_WEB_CONFIG`.
3. Путь `~/.config/ticket/web.toml`.

## 4. Запуск и остановка

### 4.1. Запусти сервер

1. Выполни команду: `tk web`.
2. Найди в выводе строку с адресом: `tk web: http://127.0.0.1:7420/`.
3. Открой этот адрес в браузере.

Команду можно выполнить из любого каталога.
Сервер не открывает браузер сам.

### 4.2. Параметры команды

| Параметр | Действие |
|---|---|
| `--port N` | Задаёт порт |
| `--port 0` | Просит у системы свободный порт |
| `--config PATH` | Задаёт путь к файлу настроек |
| `--help` | Показывает справку |

Сервер выбирает порт в таком порядке:

1. Параметр `--port`.
2. Ключ `port` в файле настроек.
3. Значение `7420`.

### 4.3. Останови сервер

Нажми `Ctrl-C` в терминале сервера.

### 4.4. Примени новые настройки

1. Измени файл настроек.
2. Останови сервер.
3. Запусти сервер снова.

### 4.5. Коды завершения

| Код | Причина |
|---|---|
| 0 | Пользователь остановил сервер |
| 1 | Ошибка в файле настроек или занятый порт |
| 2 | Неизвестный параметр команды |

## 5. Страницы

| Адрес | Содержимое |
|---|---|
| `/` | Доска с дорожкой для каждого проекта |
| `/?flat=1` | Сводная доска без дорожек |
| `/p/<name>` | Доска одного проекта |
| `/p/<name>/<id>` | Страница тикета |
| `/p/<name>/<id>/edit` | Форма правки тикета |

Верхняя строка каждой страницы содержит ссылки:
- `Lanes` открывает доску с дорожками.
- `Flat` открывает сводную доску.
- Имя проекта открывает доску этого проекта.

## 6. Колонки

| Колонка | Правило |
|---|---|
| `Blocked` | Статус `open`, тикет имеет блокер |
| `Ready` | Статус `open`, тикет не имеет блокера |
| `In progress` | Статус `in_progress` |
| `Closed` | Статус `closed` или `done` |

Дополнительные правила:
- Тикет `in_progress` с блокером остаётся в колонке `In progress`. Его карточка имеет цветную рамку.
- Тикет с неизвестным статусом находится в колонке `Ready`. Карточка показывает этот статус.
- Число в заголовке колонки показывает количество тикетов.
- Счётчик `N open` в дорожке показывает количество незакрытых тикетов.

### 6.1. Порядок карточек

| Колонка | Порядок |
|---|---|
| `Blocked`, `Ready`, `In progress` | По приоритету, затем по ID |
| `Closed` | От новых к старым, по времени последней заметки |

### 6.2. Число карточек в колонке `Closed`

| Страница | Число карточек |
|---|---|
| `/` | 5 последних на проект |
| `/?flat=1` | 5 последних на проект |
| `/p/<name>` | 50 последних |
| `/p/<name>?closed=all` | Все |

Ссылка `N more` открывает следующий уровень списка.

## 7. Карточка

Карточка показывает:
- ID тикета;
- приоритет в виде `P0`–`P4`;
- тип тикета;
- название;
- теги;
- блокеры, после знака ⛔;
- ID родителя, после знака ↑;
- имя проекта, только на сводной доске.

Цвет левой границы карточки совпадает с цветом проекта.
Нажми на карточку, чтобы открыть страницу тикета.

### 7.1. Карточка `unparsable`

Сервер показывает карточку `<файл> unparsable`, если не может разобрать файл.
Такая карточка не имеет страницы тикета и формы правки.

Причины:
- файл не имеет блока front matter;
- файл не имеет строки названия `# ...`;
- кодировка файла отличается от UTF-8;
- строки файла заканчиваются на CRLF;
- поле `id` отличается от имени файла.

Исправь файл в редакторе. Команда `tk lint` показывает часть этих ошибок.

## 8. Поиск

1. Введи текст в поле `Search`.
2. Доска скрывает карточки без этого текста.
3. Очисти поле, чтобы вернуть все карточки.

Поиск проверяет имя проекта, ID, название и теги.
Поиск не учитывает регистр.
Поиск не проверяет описание и заметки. Для них используй `tk find`.
Браузер помнит текст поиска до закрытия вкладки.

## 9. Автообновление

Страница обновляет себя, когда файл тикета меняется на диске.
Задержка составляет до двух секунд.
Текст в поле `Search` сохраняется.

Форма правки себя не обновляет. Это защищает набранный текст.

## 10. Страница тикета

Страница показывает:
- название;
- статус, тип, приоритет, исполнителя, теги, дату создания;
- родителя и дочерние тикеты;
- тикеты, от которых зависит этот тикет (`Depends on`);
- тикеты, которые зависят от этого тикета (`Blocks`);
- связанные тикеты (`Links`);
- три блока текста;
- другие разделы файла;
- заметки.

Сервер показывает текст без обработки Markdown.
Запись `missing` рядом с ID означает, что файла этого тикета нет.

## 11. Правка тикета

### 11.1. Что можно изменить

| Поле формы | Часть файла |
|---|---|
| `Title` | Строка названия `# ...` |
| `Description` | Текст между названием и первым заголовком `## ` |
| `Design` | Раздел `## Design` |
| `Acceptance Criteria` | Раздел `## Acceptance Criteria` |

Доска не меняет статус, зависимости, связи, теги, приоритет и заметки.
Для них используй команды `tk`.

### 11.2. Измени тикет

1. Открой страницу тикета.
2. Нажми `Edit`.
3. Измени текст в полях.
4. Нажми `Save`.

Сервер сохраняет тикет и открывает страницу тикета.
Кнопка `Cancel` закрывает форму без сохранения.

### 11.3. Правила сохранения

- Сервер записывает только изменённые поля.
- Пустое поле `Design` или `Acceptance Criteria` удаляет раздел вместе с заголовком.
- Новый раздел `Design` сервер ставит после описания.
- Новый раздел `Acceptance Criteria` сервер ставит после раздела `Design`.
- Смена названия добавляет в тикет заметку `Edited: title ...`.
- Смена блока текста заметку не добавляет.
- Сервер не выполняет `git commit`. Закоммить изменение сам.

### 11.4. Запрещённый текст

Сервер отклоняет сохранение в трёх случаях:

| Случай | Причина |
|---|---|
| Пустое название или название из нескольких строк | Название занимает одну строку файла |
| Строка `---` в блоке текста | `tk` читает её как границу front matter |
| Строка с началом `## ` в блоке текста | Такая строка начинает новый раздел |

Сервер проверяет только изменённые поля.
Строка с началом `# ` разрешена.

### 11.5. Конфликт правки

Конфликт возникает, если название или блок текста изменился на диске после открытия формы.
Сервер показывает сообщение `the ticket changed on disk - compare and save again`.
Сервер ничего не записывает.

Действия:

1. Найди под полем блок `On disk now`. Блок показывает текст с диска.
2. Сравни текст с диска со своим текстом.
3. Перенеси нужные части в поле.
4. Нажми `Save` ещё раз.

Второе сохранение заменяет текст на диске текстом из полей.

Новая заметка или смена статуса на диске конфликт не вызывает.

## 12. Устранение неполадок

| Признак | Причина | Действие |
|---|---|---|
| `config file not found` | Файла настроек нет | Создай файл по разделу 3 |
| `no [[project]] entry` | Файл настроек не содержит проектов | Добавь блок `[[project]]` |
| `project name ... must match` | Имя проекта содержит запрещённый символ | Измени ключ `name` |
| `project name ... is used twice` | Два проекта имеют одно имя | Измени один ключ `name` |
| `cannot listen on 127.0.0.1:<port>` | Порт занят | Останови другую программу или задай `--port` |
| Дорожка показывает `.tickets not found` | Каталог проекта не содержит `.tickets/` | Исправь ключ `path` |
| Дорожка показывает `tk blocked failed` | Команда `tk` завершилась с ошибкой | Выполни `tk blocked` в каталоге проекта |
| Карточка `unparsable` | Файл не является тикетом | Смотри раздел 7.1 |
| Форма показывает `tk set failed` | Плагин `ticket-set` отклонил название | Прочитай текст ошибки под сообщением |
| Ответ `403 Forbidden` | Адрес в браузере отличается от `127.0.0.1` и `localhost` | Открой адрес из вывода `tk web` |
| Тикет закрыт, но доска показывает его открытым | Тикет закрыт в другой ветке | Смотри раздел 18 |
| Страница не обновляет себя | Открыто больше шести вкладок доски | Закрой лишние вкладки |

# Часть 2. Как работает

## 13. Состав

| Файл | Назначение |
|---|---|
| `plugins/ticket-web` | Весь плагин: сервер, HTML, CSS, JavaScript |
| `features/ticket_web.feature` | Сценарии тестов |
| `features/steps/web_steps.py` | Шаги тестов |

Плагин использует только стандартную библиотеку Python.
CSS и JavaScript хранятся в файле плагина как строки.
Шага сборки нет.

## 14. Схема работы

```
  браузер                     сервер tk web                     диск
 ─────────                   ───────────────                   ──────
  GET /            ───────►  сверка отпечатка каталога  ────►  .tickets/*.md
                             снимок проекта             ◄────  текст файлов
                             tk blocked                 ────►  список блокировок
  HTML             ◄───────  сборка страницы

  GET /events      ───────►  поток событий
                             наблюдатель, раз в секунду ────►  .tickets/*.md
  событие          ◄───────  файл изменился
  GET / (повтор)   ───────►  новый снимок

  POST .../edit    ───────►  проверка хеша
                             tk set <id> title          ────►  название, заметка
                             замена блоков текста       ────►  временный файл, замена
  303              ◄───────
```

## 15. Чтение тикетов

Сервер читает файлы `.tickets/*.md` сам.
Команда `tk query` не подходит: она не возвращает название и текст.

Порядок разбора файла:

1. Сервер берёт front matter между двумя первыми строками `---`.
2. Сервер читает пары `ключ: значение`. Список имеет вид `[a, b]`.
3. Сервер берёт название из первой строки с началом `# `.
4. Сервер делит остальной текст по строкам с началом `## `.
5. Текст до первого заголовка `## ` — описание.
6. Разделы `Design`, `Acceptance Criteria` и `Notes` получают свои поля.
7. Любой другой раздел сервер показывает только для чтения.

Если заголовок `## Design` встречается дважды, форма правит первый раздел.
Второй раздел сервер показывает только для чтения.

### 15.1. Список блокировок

Сервер не вычисляет блокировку сам.
Сервер выполняет `tk blocked` в каталоге проекта.
Первое слово каждой строки вывода — ID заблокированного тикета.
Правило блокировки остаётся в одном месте: в скрипте `ticket`.

Сервер пропускает вызов, если каталог не содержит тикетов.

### 15.2. Вызов `tk`

Каждый вызов `tk` подчиняется трём правилам:
- Сервер передаёт аргументы списком, без оболочки.
- Рабочий каталог вызова — корень проекта.
- Сервер задаёт переменную `TICKETS_DIR` явно.

Третье правило обязательно.
`tk` передаёт плагину `TICKETS_DIR` текущего проекта.
Без явного значения все проекты читали бы один каталог.

## 16. Снимок и слежение

Сервер хранит один снимок на проект.
Снимок содержит разобранные тикеты, список блокировок и отпечаток каталога.

Отпечаток каталога — набор троек: имя файла, время изменения, размер.

Сервер сверяет отпечаток в двух случаях:
- при каждом запросе страницы;
- раз в секунду, в отдельном потоке-наблюдателе.

Если отпечаток изменился, сервер строит снимок заново.
Сверка при запросе даёт свежую страницу сразу после сохранения.
Наблюдатель нужен, чтобы оповестить открытые страницы.

Сервер строит все снимки до печати адреса.
Поэтому любое изменение после запуска вызывает событие.

## 17. Автообновление страницы

1. Страница открывает соединение `GET /events` (Server-Sent Events).
2. Сервер держит соединение открытым.
3. Наблюдатель замечает изменение и будит все соединения.
4. Сервер отправляет событие с именем проекта.
5. Сценарий страницы запрашивает тот же адрес повторно.
6. Сценарий заменяет содержимое элемента `<main>`.
7. Сценарий применяет фильтр поиска снова.

Каждые 15 секунд сервер отправляет пустую строку-комментарий.
Она удерживает соединение открытым.
Сервер замечает закрытую вкладку при следующей отправке.

## 18. Доска и ветки git

Доска показывает рабочее дерево по пути из файла настроек.
Доска не знает о ветках и worktree.

Следствия:
- Тикет, закрытый в другой ветке, остаётся открытым на доске до слияния.
- Смена ветки в каталоге проекта меняет содержимое доски.
- Правка с доски попадает в текущую ветку каталога проекта.

## 19. Запись тикета

### 19.1. Обнаружение конфликта

1. Сервер вычисляет хеш SHA-256 четырёх значений: названия и трёх блоков текста.
2. Форма хранит этот хеш в скрытом поле `base`.
3. При сохранении сервер читает файл заново и вычисляет хеш снова.
4. Разные хеши означают конфликт. Сервер отвечает кодом 409.

Хеш не охватывает front matter и заметки.
Поэтому заметка агента или смена статуса не мешают сохранению.

### 19.2. Порядок сохранения

Сервер выполняет шаги под блокировкой проекта:

1. Проверяет наличие всех пяти полей формы.
2. Читает файл с диска.
3. Сравнивает хеш с полем `base`.
4. Находит изменённые поля.
5. Проверяет изменённые поля по разделу 11.4.
6. Меняет название командой `tk set <id> title -- <текст>`.
7. Читает файл ещё раз: `tk set` изменил его.
8. Заменяет изменённые блоки текста.
9. Записывает временный файл `.<id>.md.tmp` в тот же каталог.
10. Заменяет файл тикета временным файлом одной операцией.
11. Строит снимок проекта заново.
12. Отвечает кодом 303 с адресом страницы тикета.

Имя временного файла не заканчивается на `.md`. Поэтому `tk` его не читает.

### 19.3. Что сервер не меняет

Сервер копирует без изменений:
- front matter;
- строку названия, если название не менялось;
- раздел `Notes`;
- разделы с другими заголовками;
- неизменённые блоки текста.

Сервер читает файл без преобразования концов строк.
Символ `CR` в заметке остаётся на месте.

Текст из формы сервер приводит к одному виду:
- заменяет `CRLF` на `LF`;
- убирает пустые строки в начале и в конце.

### 19.4. Коды ответа формы

| Код | Значение |
|---|---|
| 303 | Тикет сохранён или не изменился |
| 400 | Поле отсутствует, текст запрещён или `tk set` вернул ошибку |
| 403 | Заголовок `Origin` принадлежит другому сайту |
| 404 | Проект или тикет не найден |
| 409 | Конфликт правки |
| 500 | Сервер не смог записать файл |

## 20. Безопасность

Сервер не имеет авторизации. Его защищают пять правил:

| Правило | Защита |
|---|---|
| Сервер слушает только `127.0.0.1` | Другие компьютеры не видят сервер |
| Сервер проверяет заголовок `Host` | Чужой домен не может обратиться к серверу через DNS |
| Сервер проверяет заголовок `Origin` запроса POST | Чужой сайт не может отправить форму |
| Сервер ищет проект и тикет по ключу в памяти | Текст адреса не попадает в путь файла |
| Сервер экранирует весь текст в HTML | Текст тикета не исполняется как разметка |

Сервер никогда не передаёт `--force` и не вызывает `tk super`.

Не открывай порт сервера для сети.

## 21. Ограничения

- Доска не меняет статус, зависимости, связи и заметки.
- Доска не создаёт тикеты.
- Доска не обрабатывает Markdown.
- Строка `## ` внутри блока кода делит раздел на форме.
- Блокировка проекта действует только внутри сервера. Агент может записать файл во время сохранения.
- Заголовок раздела в другом регистре, например `## design`, считается другим разделом.
- Сервер не замечает правку, которая сохранила размер файла и время изменения.
- Скрипты публикации в Homebrew и AUR не знают о зависимостях плагина.

## 22. Тесты

Выполни все тесты проекта:

```sh
make test
```

Выполни только тесты доски:

```sh
uv run --with behave behave features/ticket_web.feature
```

Тест запускает настоящий сервер на свободном порту.
Тест отправляет запросы HTTP и проверяет HTML и файлы тикетов.
